# vig conventions

Generated by vig's cloud kit from `global/CLAUDE.md`. Edit it in vig, not here. This repo's `.claude/` folder carries the dev team: agents, skills, rules, and the shared standards in `.claude/vig/standards/`.

## Entry points

| Entry | Use it for |
|---|---|
| `/senior <ticket>` | implement one ticket in a worktree with the senior agent; stops before push and prints the push and PR commands |
| `/review-pr <pr-url>` | review + QA + specialists against an existing PR; verdicts to `.team-verdicts/` by default, `--pr` to post them |
| `plan-project` | work that starts from a concept, a client brief, or a request for an estimate: intake, plan with a critical path and a range, proposal, tickets |
| `decompose-ticket` | cut a ticket into reviewable pieces before writing code |
| `design` | write or review an RFC before a large change |
| `rebase-auditor` | check a rebase for silent deletions before merging it |

## Agents

Implementation and judgment run on sonnet (`senior`, `review`, `qa`, `tech-pm`); narrow diff checks run on haiku at low effort (`spec-compliance`, `a11y-audit`, `perf-check`, `architecture-audit`); `synthesizer` runs on opus. Every agent declares its `tools:`, so read-only agents cannot write.

**Council.** Fan out to `critical-thinker`, `know-it-all`, `creative-peer`, and `snidely` in one message, then run `synthesizer` over what they returned. `baseline` is the unprimed control. `snidely` is an inverse signal: enthusiasm is the warning, and the closing `ACTUAL RISK:` line is the payload.

## Conventions

- `git push`, `gh pr create|merge|comment|edit`, `gh issue create|close|comment`, and `gh release` prompt every time in local sessions (user-level `permissions.ask`). In a cloud session, follow `cloud-github.md`. When a human should decide, print the command rather than running it.
- Shell commands that name `.env` files, private keys, or credential files are blocked by the `secret-guard` PreToolUse hook; ask the user for the value instead. Template files such as `.env.example` pass.
- Code standards: `$CLAUDE_PROJECT_DIR/.claude/vig/standards/react-nextjs.md` is the full rule set and `architecture.md` its layer rules. A project's `.claude/standards/stack-decisions.md` settles the rules that adapt per project, and its own `architecture.md` replaces the default.
- `code-standards` and `quality-gates` rules load only when a JS/TS file or `package.json` is touched; `scope-discipline` always loads.
